# Photo App (Flutter client)

A Google Photos–style Flutter client for the Flask backend in
`photobackend/`. Covers login/register, camera-roll style grid, upload
(gallery or camera), full-screen viewer, favorites, trash/restore/
permanent delete, and albums.

## Setup

This folder ships `lib/` and `pubspec.yaml` only — the Android/iOS
platform folders (`android/`, `ios/`, gradle files, Xcode project, etc.)
are generated by the Flutter tool itself and are best created fresh
rather than hand-assembled, since they're tied to your installed
Flutter/Xcode/Android SDK versions.

```bash
# 1. Create a fresh Flutter project shell
flutter create photo_app
cd photo_app

# 2. Replace the generated lib/ and pubspec.yaml with the ones here
rm -rf lib
cp -r /path/to/this/lib .
cp /path/to/this/pubspec.yaml .

# 3. Install dependencies
flutter pub get

# 4. Add permissions (camera/gallery/network) -- see the two snippet
#    files in this folder and where to paste them:
#      android_manifest_permissions.xml -> android/app/src/main/AndroidManifest.xml
#      ios_info_plist_permissions.xml   -> ios/Runner/Info.plist

# 5. Run
flutter run
```

On first launch the app asks for your backend's URL (e.g.
`http://192.168.1.20:5009` for a phone on the same LAN as your dev
machine, or your real domain once deployed), then shows the login/
register screen.

## Architecture

```
lib/
├── main.dart                    # app entry, theme, routes to server-setup/login/home
├── models/                      # plain Dart classes mirroring the API's JSON
│   ├── user.dart
│   ├── media_item.dart
│   └── album.dart
├── services/                    # thin wrappers that call the REST API
│   ├── api_client.dart          # token storage + auto-refresh + request helpers
│   ├── auth_service.dart
│   ├── media_service.dart
│   └── album_service.dart
├── providers/                   # app state (ChangeNotifier + provider package)
│   ├── auth_provider.dart       # session state, drives which screen shows
│   ├── media_provider.dart      # photo grid: pagination, upload queue, actions
│   └── album_provider.dart      # album list state
├── screens/
│   ├── server_setup_screen.dart # first-run: enter backend URL
│   ├── login_screen.dart / register_screen.dart
│   ├── home_screen.dart         # bottom nav: Photos / Albums / Trash / Profile
│   ├── photos_screen.dart       # grid + upload + multi-select trash, reused for Trash tab
│   ├── photo_detail_screen.dart # full-screen swipeable viewer
│   ├── albums_screen.dart / album_detail_screen.dart
│   ├── add_to_album_sheet.dart  # bottom sheet from the detail viewer
│   └── profile_screen.dart      # storage usage bar, logout
└── widgets/
    ├── photo_grid_tile.dart
    └── upload_banner.dart
```

### Why these choices

- **`provider` package**, not Bloc/Riverpod — smallest amount of
  ceremony for an app this size, and it's what most Flutter tutorials
  teach first, so it's easy to extend later.
- **One `MediaProvider` class, three tabs.** `PhotosScreen` takes
  `trashed`/`favoritesOnly` flags and builds its own `MediaProvider`
  scoped to that filter — the "All Photos" grid, the Trash tab, and (if
  you wire up a filter chip) a Favorites view are the same widget over
  different server queries, instead of three near-duplicate screens.
- **`flutter_secure_storage`** for the JWT tokens and server URL —
  Keychain on iOS, EncryptedSharedPreferences on Android, rather than
  plain `shared_preferences`.
- **No local database / full offline cache yet.** The grid is a
  straightforward paginated `GET /media` with infinite scroll and
  pull-to-refresh — simple to reason about and enough for normal use.
  The backend's `/sync` endpoint (delta sync with tombstones) is there
  and ready; see "Extending this app" below for what wiring it in would
  look like.

## Known limitation: not compiler-verified

This code was written and reviewed carefully, but the Dart/Flutter SDK
wasn't available in the environment I built this in, so it hasn't been
run through `flutter analyze` or actually compiled. The `Future<void>
Function()` used as several button callbacks is intentionally valid
Dart (functions returning non-void are assignable to `void Function()`
callback slots), but please run:

```bash
flutter analyze
```

right after copying the files in, and treat the first `flutter run` as
a real first test pass, not a formality.

## Testing against the backend

1. Start the Flask backend (see `photobackend/README.md`), noting the
   machine's LAN IP (not `127.0.0.1` — your phone/emulator can't reach
   that): e.g. `http://192.168.1.20:5009`.
2. Run `flutter run` on a device on the same Wi-Fi network, or use an
   Android emulator with `http://10.0.2.2:5009` (the emulator's alias
   for the host machine).
3. If you test with `flutter run -d chrome` (Flutter Web), you'll also
   need to add CORS support to the backend (`pip install flask-cors`,
   then `CORS(app)` in `app.py`) — browsers enforce CORS, phones don't.

## Extending this app

- **Offline-first sync**: swap `MediaProvider.refresh()`/`loadMore()`
  for a local database (`drift` or `sqflite`) fed by `GET
  /sync?since=<token>`, so the grid reads from disk instantly and syncs
  in the background. This is the biggest single upgrade if you want it
  to feel like the real Google Photos app on a flaky connection.
- **Automatic camera-roll backup**: add the `photo_manager` package to
  enumerate the device's photo library, call `/media/check` with their
  checksums, and upload whatever's missing — pair with `workmanager`
  (Android) for periodic background backup.
- **Byte-level upload progress**: the current `uploadFile()` in
  `api_client.dart` reports 0%/100% only, since plain `http` doesn't
  expose streaming upload progress. Swap in `dio`, which supports an
  `onSendProgress` callback, if you want a smooth per-file progress bar
  for large videos.
- **Video thumbnails**: the backend doesn't generate them yet either
  (needs `ffmpeg` server-side) — see its README for the hook point.
